#+TITLE: Clojure + PySide6 示例

* Clojure / libpython-clj2 / PySide6

=clojure/= 目录通过 [[https://github.com/clj-python/libpython-clj][libpython-clj2]] 调用 PySide6，提供与主线章节对应的 Clojure 示例。

** 前置要求

- Clojure CLI
- JDK 17+
- Python 3.9+
- 当前 shell 中可导入 =PySide6= 的 Python

关键点:

- 本目录当前没有单独提交 =python.edn= 配置文件。
- 最稳妥的做法是先激活装有 =PySide6= 的 Python 环境，再执行 =clj -M:<alias>=。

** 快速开始

#+begin_src bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install PySide6

cd clojure
clj -M:ch01-core-meta-object
#+end_src

运行前可先验证当前 Python:

#+begin_src bash
python -c "import PySide6; print(PySide6.__version__)"
#+end_src

** Alias 命名规则

每个示例都在 =deps.edn= 中提供 alias，命名模式为:

#+begin_example
chXX-<section>-<example>
#+end_example

例如:

- =01_core/01_meta_object= -> =clj -M:ch01-core-meta-object=
- =04_qml/03_javascript= -> =clj -M:ch04-qml-javascript=
- =12_project/todo_app= -> =clj -M:ch12-project-todo-app=

** 运行提示

- macOS GUI 示例要求主线程启动；仓库里的 alias 已经包含 =-XstartOnFirstThread=。
- 若只想做 QML/Quick 的 headless 冒烟验证，部分示例支持 =QT6_TUTORIAL_AUTOQUIT=。
- WebSocket、HTTP、多媒体、GUI 测试等示例可能依赖外部环境或设备，不适合无差别批量运行。

示例:

#+begin_src bash
cd clojure
QT6_TUTORIAL_AUTOQUIT=200 clj -M:ch04-qml-basics
#+end_src

** Troubleshooting

*** =No module named 'PySide6'=

通常不是 Clojure 依赖问题，而是 =clj= 运行时抓到的 Python 环境不对。先在同一个 shell 里确认:

#+begin_src bash
python -c "import PySide6"
#+end_src

如果这里失败，先修 Python 环境，再跑 =clj=。

*** 你按旧文档去找 =python.edn=

本仓库当前没有提交该文件。优先使用“激活 Python 环境后再运行 =clj=”的方式，不要依赖一个不存在的本地配置模板。

*** macOS GUI 启动失败

不要绕过 =deps.edn= 里的 alias 直接手写 JVM 启动参数。alias 已经处理了 =-XstartOnFirstThread=。

*** QML / Quick 示例不退出

这类示例会进入 Qt 事件循环。若只是自动化检查，可优先选择支持 =QT6_TUTORIAL_AUTOQUIT= 的示例。

*** 信号断开或某些高级交互行为与 Python 版不同

这通常来自 libpython-clj2 与 PySide6 的桥接差异。更底层的经验记录见 [[file:AGENTS.md][AGENTS.md]]。
